# LFH-459 UHS-Höhenführung Implementation Plan

**Goal:** Der Grundriss nutzt in jeder Dichtestufe die tatsächlich verbleibende Fensterhöhe.

**Architecture:** `EinsatzSeite` erhält den optionalen Slot `fensterInhalt: { inhalt, mindestHoehe? }`. Ein eigener `FensterRahmen` misst den äußeren Dokumentabstand (Chat-Muster, ergänzt um ResizeObserver); innerhalb des Rahmens teilen sich Kopf und Grundriss die Höhe per Flexbox. Die gemessene Kopfhöhe plus Mindest-Arbeitsfläche bildet den Boden für sehr lange Köpfe. `children` folgen im normalen Dokumentfluss. Ohne Slot bleibt die bisherige Struktur erhalten.

**Tech Stack:** React 19, Ant Design 6, TypeScript, Playwright, Vitest.

**Spec:** https://app.clickup.com/t/86cb82nd4

## Scope und Grenzen

- Nur LFH-459; keine Änderung an Fachaktionen, Berechtigungen oder Datenabfragen.
- Kein geschätzter Abzug für die Kopfhöhe, auch keine dichteabhängige Tabelle solcher Schätzwerte.
- Andere EinsatzSeite-Konsumenten haben keinen Viewport-Abzug. Lagekarte (`100vh - 120px`) und Chat (gemessen) verwenden das Primitiv nicht.
- Material/Bewegungen bleiben unter dem Grundriss per Seitenscroll erreichbar.
- Auslieferung über einen Pull Request auf main; bestehende Änderungen im Haupt-Checkout bleiben erhalten.

## Risiken

Prozenthöhen innerhalb der mobilen Ant-Tabs sind gesondert im Browser zu prüfen. Ein Resize während des Seitenscrolls darf die Resthöhe nicht vergrößern; deshalb Dokumentkoordinate statt bloßem Viewport-top. Der Default des Primitivs darf keine zusätzliche Höhenbegrenzung bekommen.
